## Data Files Structure

### cv-data.js
Contains the main CV information organized by profile:
- Personal information (shared across all profiles)
- Professional summary (profile-specific for each role: delivery-manager, frontend-lead, technical-project-manager)
- Work experience (shared across all profiles)
- Selected projects (shared across all profiles)
- Education (shared across all profiles)
- Certifications (shared across all profiles)
- Languages (shared across all profiles)
- Profile-specific content for title and summary

The file uses a hierarchical structure where profile-specific content (title, summary) has nested objects for each profile, while shared content (experience, education, etc.) is defined once and used across all versions.

### skills.js
Organized technical skills by profile:
- **delivery-manager**: Skills focused on delivery management, stakeholder coordination, Agile methodologies, and delivery processes
- **frontend-lead**: Skills focused on frontend development, technical leadership, web technologies, and accessibility
- **technical-project-manager**: Skills focused on project management, technical coordination, IT project delivery, and leadership
- **default**: Common skills across all profiles

Each profile has categories of skills relevant to that specific role, allowing the build process to select the appropriate skill set for each CV version.

### versions.js
Configuration file for CV version generation:
- Defines the three profile versions (delivery-manager, frontend-lead, technical-project-manager)
- Specifies output directories and metadata for each version
- Controls which versions are generated by the build process

This file serves as the central configuration for the multi-version build system.

### keywords.js
SEO and search optimization keywords organized by:
- Job titles
- Technical keywords
- Accessibility keywords
- Project management keywords
- Soft skills
- Industry keywords

## Build Process

**IMPORTANT:** When making changes to any data files (`cv-data.js`, `skills.js`, `versions.js`), you must run the build script to generate all CV versions:

```bash
npm run build
```

### Build Commands
- `npm run build` - Generate all CV versions for all profiles and languages
- `npm run dev` - Build and open development version from src/
- `npm run preview` - Build and open production version from dist/

### Build Process
The build script automatically:
1. Reads configuration from `data/versions.js` to determine which profiles to generate
2. Reads CV data from `data/cv-data.js` (shared and profile-specific content)
3. Reads skills data from `data/skills.js` (profile-specific skills)
4. For each profile defined in versions.js:
   - Combines shared data with profile-specific content (title, summary, skills)
   - Generates a personalized cvData object for that profile
   - Creates the directory structure: `dist/versions/<profile>/en/` and `dist/versions/<profile>/es/`
   - Copies and customizes HTML, CSS, and JavaScript files for each language
5. Updates the development version in `src/app.js` with default profile data

### Build Output
The compiled files are placed in the `dist/versions/` directory with the following structure:
```
dist/versions/
├── delivery-manager/
│   ├── en/ (with delivery-manager specific data)
│   └── es/ (with delivery-manager specific data)
├── frontend-lead/
│   ├── en/ (with frontend-lead specific data)
│   └── es/ (with frontend-lead specific data)
└── technical-project-manager/
    ├── en/ (with technical-project-manager specific data)
    └── es/ (with technical-project-manager specific data)
```

**Note:** This build process is necessary because the project uses inlined data in `app.js` for browser compatibility without requiring a bundler. The `dist/versions/` folder contains the production-ready compiled files for each profile and language combination.
